# 模型接力 · dsh-model-failover

把 **已经接入 dsh 的全部模型**排成优先级队列，再把这个插件本身当成**一组「模型」**——
**一条队列就是模型选择器里的一个模型**。用户在模型选择里挑中哪条（默认那条叫
`默认模板`，也可以自己新建、改名），任务就按那条队列的顺序去跑：靠前的先上，不行就自动
往下换，直到任务跑完。

## 它解决什么

一个模型不能输出，往往是这几种：额度用尽、余额不足、key 失效、路由挂了、上游 5xx。
以前遇到这些，任务当场就断了。现在：

1. 先用**第一个**模型跑；
2. 它出问题 → 把**同一个请求原样**再发几次（默认 2 次，为了换掉背后那个坏账号），
   还是不行再补一句「继续」试一次；
3. 仍然不行 → 换**第二个**模型，这一跳补上「继续」，接着跑；
4. 依次往下，直到某个模型把任务跑完；
5. 某个模型今天在这个会话里出过这种问题 → **这个会话今天不再从它开始**，直接用排在它后面、
   已经验证过能用的那个（别的会话照常可以先用它）；
6. 到了**第二天设定时间**（默认 01:00，可改），隔离自动清空，重新从第一个开始试。

另外，**整轮**以失败告终、或被 token 上限截断时（模型自己没坏，只是这一轮没跑完），
插件会替你自动补一句「继续」接着做 —— 见下面的「DSH 异常」。

## 装好之后长什么样

**模型选择器里多出几条**（provider `model-failover`）——**一条队列就是模型选择器里的一个
模型**。默认那条叫 `默认模板`；你在设置页新建一个模板，模型选择器里就多一项，名字就是你
给模板起的名字。会话里选了哪条，那个会话就往那条队列上跑。

**设置 → 模型接力**（在「模型」那一节下面）。同一类设置放在一起，从上到下依次是：

| 区块 | 作用 |
| --- | --- |
| 今日状态 | 今天是哪天、距下次重置还有多久、当前起点、今天隔离了几个（重置时间就在这里） |
| 队列模板 | 一条模板一行：改名、切到哪条去编辑（`编辑`）、`测试连接`、新建、`✕` 删除（会先问一次）。条数不限，新建出来是空队列；卡片底部两颗按钮把模板存成一个 JSON 文件、或者从这样的文件读回来 |
| 「某模板」的队列 | 正在编辑的那条模板的候选清单，每行前面是今天的**失败/成功次数**、一个**并发上限**输入框、一个**思考强度**下拉框，按住整行拖到新位置就能排序，`✕` 移除；**右键任意位置弹小窗看/改该模型的上下文窗口**；下面可以从目录里加回来 |
| 模型异常 | 总开关、同一个模型失败后重试几次、多久没输出算卡住、被限流后绕开多久、并发模型收工之后再歇几秒、按真正跑的那个模型记账（下面一行写着到底接管上没有）、全部隔离时要不要硬试。开着的时候，队列里的模型一直在后台自动接力 |
| DSH 异常 | 总开关、两种触发、**各自**的次数上限、每次失败后等多久再补（见下）。对整个 DSH 生效，不限于接力 |
| 外观 | 会话页「隔离队列」里显示哪些会话：子智能体的（默认关）、其他工作区的（默认开） |
| 事件日志 | 每次隔离/复活/轮换/限流冷却/自动补发都留一条；记不记、留多少条也在这里 |

**「测试连接」的结论会留到你刷新页面为止。** 一颗模板一颗按钮，点了就按顺序把你这条
队列里的模型各探一遍，通不通、几百毫秒，写在每个模型名字后面。探到一半切去看会话、去改
别的设置，都不要紧：探测照样跑完，切回来结论还在 —— 面板关掉不等于把体检叫停，也不会
因为换了个页面就从头再探一遍。悬停能看见这个结论是什么时候测的，所以隔了一阵再看到它时，
你心里有数它是新的还是旧的。

这份结论**不写进配置文件**：它是「刚才那一刻」的体检结果，存下来就成了永久结论 ——
账号掉了、额度用完了，它还理直气壮写着「通」。刷新页面清空它，那时候重测一遍是合理的。

**账单记在谁名下。** 这条路由在模型选择器里叫「模型接力」，可真正跑的是队列里的某一个模型。
默认情况下宿主会把它记成一个叫 `model-failover:default` 的假模型 —— 一天下来那一行几百次
调用，点开看不出钱花在谁身上。现在账单记在**真正跑的那一个**身上，各按各的价算。

做法是接管宿主的计费入口（把 dsh-cost-meter 挂在全局的那座桥的 `createScope` 包一层），
不是伪造数据：外层这一次「模型接力」调用不再入账，内层那个真实候选自己作为一次独立调用落账。
这两件事必须成对 —— 只让外层不记会整单漏计，只让内层落账会一笔记两次。所以「外层不记」是
**有条件的**：这一趟真的见过内层的真实调用才生效；取不到桥、桥的形状变了、或者这一趟压根
没往下走（模板是空的），就原样退回旧行为 —— 宁可名字记错，也不漏记、不双记。

计费桥是 dsh-cost-meter 在它自己加载时挂上去的，谁先加载看插件顺序，所以本插件会在
`globalThis` 的那个位置上装一个**访问器**：桥什么时候来、被换掉、被删掉再重挂，都会被
顺手包好，不用等人再来装一次（另外启动后 0 / 200 / 500 / 1000 / 2000 / 4000 毫秒还会
各试一次，装上了日志里说一句）。每派发一次真实调用也顺手补一眼 —— 桥被 cost-meter
卸载又重装时，访问器会跟着一起消失，这一眼就是补它。

**接管上了没有，设置页那一行写着。** 开关下面那颗小标写着「已接管 / 没接管」，后面跟着
「这一进程：路由名调用 N 次，其中 M 次记到了真实模型名下」。以前这件事完全不可见：开关是
开的、界面照常跑、日志一片安静，只有翻账本才会发现整天都记在「模型接力」名下。三种情形
都看得出来 —— 还没接到桥（`没接管` + 在等什么）、正常（`已接管` + N/M）、以及最阴的一种：
接上了却一次都没落账（`已接管`，但会直接说「这些调用一次都没落到真实模型名下」并告诉
你下一步怎么做）。关掉这颗开关就不再提这些。

关掉这颗开关就回到旧行为；老配置里没这个键，也当作开着。

**把隔离划掉之后，下一趟就回队首。** 会话页上那颗 ✕ 把某几条隔离记录划掉的时候，正在跑的那
一趟**不打断** —— 用户手上正写着的半句话不该被从中间换个人接着写。等这一趟自己输出完，下一次
请求就**从队列第一个没被隔离的模型重新开始**，而不是继续在这个替补身上跑下去。

这里只认**排在我前面**的那几位：拿名额的时候他们被隔离着、现在被放出来了、而且位置在我前面，
就把座位还回去（**不带**收工冷却 —— 这一趟活还没干完，没理由让上游先歇）。划掉的是排在后面的
记录、或者划掉之后前面仍旧全被隔离，都不会动正在跑的这一趟 —— 那种时候换人纯属瞎折腾。
它也不跨会话：别的会话划名单不影响你这一趟的座位。

**注意：** 不同的模型（包括量化版与蒸馏版）混用可能会导致缓存命中率大幅下降，请尽量把同一模型安排在同一队列，即使是dsv41flash的0910版本和1017版本都有区别。
